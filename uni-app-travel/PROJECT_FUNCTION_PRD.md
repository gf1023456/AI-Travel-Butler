# AI Travel Butler（慧游）— 功能需求文档（PRD）

> 本文档为纯功能描述，不含任何 UI 样式细节，供 UI 设计师或原型生成智能体从零进行界面设计。

---

## 1. 项目概述

| 项 | 说明 |
|---|---|
| 产品名称 | AI Travel Butler（中文：慧游） |
| 产品定位 | 基于 AI 的智能旅行行程规划助手 |
| 目标平台 | 微信小程序（uni-app 框架） |
| 核心能力 | 自然语言生成行程、地图可视化、行程历史管理、AI 二次优化、用户配额管理、微信登录 |
| 用户角色 | 普通旅行者（需微信登录后使用核心功能） |

---

## 2. 核心用户流程

```
登录 → 探索/输入需求 → AI 生成行程 → 查看行程详情 → 地图查看路线 → （可选）优化行程 → 保存历史
```

---

## 3. 页面功能清单

---

### 3.1 首页 — 地图视图（pages/index/index）

**页面目的**：应用首页，以地图为核心载体展示行程路线与景点分布，提供全应用导航入口。

**核心功能**：
1. **地图展示**：全屏地图，支持标准地图与卫星地图切换。
2. **用户定位**：页面初始化时获取用户真实 GPS 定位，将地图中心移至用户当前位置；若获取失败则使用默认城市坐标。
3. **行程数据渲染**：从全局状态（Store）读取当前行程，在地图上渲染：
   - 景点标记（Marker）：每个景点一个标记，显示景点名称与所属天数。
   - 路线连线（Polyline）：按天分组，每天景点按顺序连线。
4. **标记详情弹窗**：点击任意地图标记，弹出该景点的详细信息，包括：名称、所属天数、时间、天气、城市、介绍、交通提示、建议游玩时长。
5. **地图导航栏**：底部固定导航栏，提供以下入口：
   - 探索（跳转行程生成页）
   - 行程（跳转行程详情页）
   - 地图类型切换（标准图 / 卫星图）
   - 历史（跳转历史记录页）
   - 我的（跳转个人中心页）

**数据来源**：`travelStore.currentPlan`

**页面状态**：
- 无行程数据：地图仅展示用户位置（或默认位置），无标记和路线。
- 有行程数据：地图中心自动移至第一个景点，显示所有标记和路线。

---

### 3.2 灵感探索（pages/explore/index）

**页面目的**：AI 行程生成的入口页，用户通过自然语言描述旅行需求，由 AI 生成个性化行程。

**核心功能**：
1. **模式切换**：两种生成模式二选一：
   - 快速探索：轻量级景点推荐，不排日程。
   - 深度排期：完整的多日行程规划，含每日时间安排。
2. **旅行风格选择（仅深度排期模式显示）**：四种预设风格，用户单选：
   - 轻装上阵
   - 深度打卡
   - 美食之旅
   - 户外探索
3. **需求输入**：多行文本输入框，用户描述旅行想法（目的地、天数、偏好等），最多 500 字。
   - 实时显示当前字数 / 最大字数。
4. **生成按钮**：根据当前模式和风格调用 AI 生成行程。
   - 生成前校验：用户必须已登录；输入不能为空。
   - 生成过程中显示 Loading。
   - 生成成功后跳转行程详情页。
   - 生成失败显示错误提示。
5. **登录拦截**：未登录用户点击生成时，提示"请先登录"并自动跳转登录页。

**数据来源**：用户输入 + `travelStore.createPlan()`

---

### 3.3 行程详情（pages/plan/plan）

**页面目的**：展示 AI 生成的行程结果，支持查看、保存、复制、导出。

**核心功能**：
1. **行程摘要**：顶部展示 AI 生成的行程整体概述文本。
2. **每日行程列表**：按天排序的景点卡片列表，每张卡片展示：
   - 天数标签（Day N）
   - 时间安排
   - 景点名称
   - 景点介绍
   - 城市（如有）
   - 天气与温度（如有）
3. **操作按钮区**：
   - 保存：将当前行程保存到历史记录（调用后端 API，失败则降级本地存储）。
   - 复制：将行程内容格式化为纯文本并写入剪贴板。
   - 导出：确认后将行程复制到剪贴板（与复制功能共享实现）。
   - 关闭：返回首页地图。
4. **空状态**：无行程数据时展示空状态提示，引导用户去生成行程。

**数据来源**：`travelStore.currentPlan`

---

### 3.4 行程优化（pages/refine/refine）

**页面目的**：对已有行程进行二次 AI 优化调整。

**核心功能**：
1. **当前行程预览**：展示当前行程的目的地和天数信息。
2. **优化需求输入**：多行文本输入框，用户描述优化方向（如增加景点、调整顺序、加入美食推荐等），最多 500 字。
   - 实时字数统计。
3. **优化提交**：
   - 校验：输入非空且当前存在行程。
   - 调用 AI 优化接口，显示 Loading。
   - 成功后提示"优化成功"，自动返回上一页。
   - 失败显示错误提示。

**数据来源**：`travelStore.currentPlan` + `travelStore.refinePlan()`

---

### 3.5 历史记录（pages/history/index）

**页面目的**：查看、载入、删除用户保存过的历史行程。

**核心功能**：
1. **登录拦截**：进入页面前检查登录态，未登录自动跳转登录页。
2. **历史列表**：展示用户保存的所有历史行程，每项展示：
   - 创建时间
   - 收藏状态（⭐ 标记）
   - 行程摘要预览（前 50 字）
3. **列表操作**：
   - 点击整项：弹出详情弹窗，展示完整行程信息（ID、时间、模型、摘要、每日景点详情）。
   - 载入按钮：将历史行程恢复到当前行程状态，并跳转行程详情页。
   - 删除按钮：二次确认后删除该条历史记录。
4. **数据降级**：后端 API 失败时，自动降级读取本地缓存数据。
5. **详情弹窗操作**：弹窗内提供"载入此方案"和"关闭"按钮。

**数据来源**：`getHistoryList()` API / 本地缓存

---

### 3.6 登录页（pages/login/index）

**页面目的**：微信用户登录授权，获取用户身份 Token。

**核心功能**：
1. **头像选择**：用户点击选择微信头像，使用微信小程序原生头像选择能力。
2. **昵称输入**：单行文本输入，用户填写或修改昵称。
3. **微信一键登录**：
   - 必须勾选用户协议和隐私政策。
   - 调用微信登录获取临时 code。
   - 将 code、昵称、头像传给后端换取 JWT Token。
   - 登录成功后保存 Token 到本地，跳转首页。
4. **手机号登录（占位）**：备用登录方式，当前仅展示入口，点击提示开发中。
5. **协议勾选**：复选框形式，未勾选时点击登录按钮提示"请先同意用户协议"。

**数据来源**：微信原生能力 + `wechatLogin()` API

---

### 3.7 个人中心（pages/mine/index）

**页面目的**：展示用户信息、配额状态、提供系统入口和退出登录。

**核心功能**：
1. **登录拦截**：未登录自动跳转登录页。
2. **用户信息展示**：
   - 头像
   - 昵称
   - 用户等级/徽章（如"精英旅行者"）
3. **今日配额卡片**：
   - 展示剩余次数、已使用次数、额外奖励次数。
   - 展示配额使用进度条（已用 / 总量）。
4. **功能菜单**：
   - 我的行程 → 跳转历史记录页
   - 设置 → 占位，提示开发中
   - 帮助与反馈 → 占位，提示开发中
5. **会员权益推广**：展示会员服务介绍。
6. **退出登录**：二次确认后清除本地登录状态，跳转登录页。
7. **底部导航栏**：与首页一致的 3 入口导航（探索 / 行程 / 我的），当前高亮"我的"。

**数据来源**：`getUserInfo()` + `getQuota()` API

## 4. 全局功能与状态

### 4.1 用户认证与登录态

- 使用 JWT Token 机制，包含 access_token 和 refresh_token。
- Token 存储在本地缓存（`uni.getStorageSync`）。
- 需要登录的页面（探索、历史、个人中心）在页面加载时自动检查登录态，未登录跳转登录页。
- HTTP 请求拦截器在 401/422 认证错误时自动清理 Token 并跳转登录页，防止重复跳转。

### 4.2 配额系统

- 每日默认 10 次 AI 行程生成配额。
- 生成行程前必须先检查配额（`getQuota`）。
- 配额不足时阻断操作，弹窗提示用户配额已用完。
- 生成成功后自动扣减配额（`useQuota`）。
- 分享等行为可增加奖励配额。

### 4.3 地图定位

- 首页初始化时获取用户真实 GPS 坐标（`uni.getLocation`，`gcj02` 坐标系）。
- 高精度模式，超时 4 秒。
- 成功则地图中心移至用户位置；失败则保持默认城市坐标。
- 地图组件原生显示用户位置蓝点（`show-location`）。

### 4.4 状态管理（Pinia）

| Store | 核心状态 | 作用 |
|---|---|---|
| **travel** | `currentPlan` | 当前激活的行程数据 |
| | `planHistory` | 本次会话内产生的行程历史 |
| | `loading` | AI 生成/优化的全局加载状态 |
| | `error` | 错误信息 |
| | `preferences` | 用户偏好缓存（模式、风格等） |
| **user** | `accessToken` / `refreshToken` | JWT 认证令牌 |
| | `nickname` / `avatarUrl` | 用户基本信息 |
| | `quota` | 配额数据（used, max, remaining, bonus） |
| | `isLoggedIn` | 登录状态布尔值 |

## 5. 数据实体定义

### 5.1 行程计划（TravelPlan）

```typescript
interface TravelPlan {
  userInput: string           // 用户原始输入文本
  modelType: string           // AI 模型类型标识
  isPlannerMode: boolean      // true=深度排期, false=快速探索
  travelMode: string          // 旅行风格: light/deep/food/outdoor
  itinerarySummary: string    // AI 生成的行程摘要
  dayPlanItinerary: DayPlanItem[]
  socialRecommendations: SocialItem[]
  evidence: any[]             // 引用来源/证据
  warnings: any[]             // 校验警告
}
```

### 5.2 每日行程项（DayPlanItem）

```typescript
interface DayPlanItem {
  day: number        // 第几天
  sequence: number   // 当天序号
  name: string       // 景点名称
  time: string       // 建议时间
  city: string       // 城市
  description: string
  lat: number        // 纬度
  lng: number        // 经度
  transit_hint: string      // 交通提示
  visit_duration: string    // 建议游玩时长
  weather_icon: string      // 天气图标
  temperature: string       // 温度
}
```

### 5.3 社交推荐项（SocialItem）

```typescript
interface SocialItem {
  title: string
  name: string
  platform: string    // 平台名称
  reason: string      // 推荐理由
  description: string
}
```

### 5.4 历史记录项（HistoryItem）

```typescript
interface HistoryItem {
  id: number
  user_input: string
  model_type: string
  provider: string
  itinerary_summary: string
  day_plan: DayPlanItem[] | Record<string, DayPlanItem[]>  // 支持数组或按天分组的字典
  social_recommendations: SocialItem[]
  evidence: any[]
  warnings: any[]
  is_favorite: boolean
  created_at: string
}
```

## 6. API 接口清单

| 模块 | 接口 | 方法 | 功能描述 |
|---|---|---|---|
| **行程** | `/plan` | POST | 创建行程。参数：userInput, modelType, isPlannerMode, travelMode |
| | `/plan/refine` | POST | 优化行程。参数：userInput, modelType, refineInstruction, basePlan |
| | `/getModel` | GET | 获取当前后端配置的 AI 模型名称 |
| **历史** | `/history/list` | GET | 分页获取历史记录列表。参数：page, page_size, favorite_only |
| | `/history/detail/{id}` | GET | 获取单条历史记录完整详情 |
| | `/history/save` | POST | 保存当前行程到历史记录 |
| | `/history/favorite` | POST | 切换某条历史的收藏状态 |
| | `/history/{id}` | DELETE | 删除指定历史记录 |
| **用户** | `/login` | POST | 微信登录。参数：code, user_info(nickname, avatar_url) |
| | `/userInfo` | GET | 获取当前登录用户信息 |
| | `/refreshToken` | POST | 使用 refresh_token 刷新 access_token |
| **配额** | `/quota/check` | GET | 查询今日配额状态 |
| | `/quota/use` | POST | 使用一次配额（扣减） |
| | `/quota/bonus` | POST | 增加奖励配额 |

**通用请求行为**：
- 请求自动携带 `Authorization: Bearer {access_token}` 请求头。
- 认证失败（401/422）时自动清除本地 Token 并跳转登录页。
- AI 生成类请求超时 180 秒，普通请求 60 秒。
- 后端返回统一格式：`{code: 0, data: {}, msg: ""}`，code=0 表示成功。

## 7. 用户操作流程图

### 7.1 首次使用流程

```
打开小程序 → 首页地图（尝试定位）→ 点击"探索"
→ 未登录 → 跳转登录页 → 微信登录 → 返回探索页
→ 输入旅行需求 → 选择模式与风格 → 点击生成
→ Loading → 生成成功 → 跳转行程详情页
→ （可选）查看地图 → （可选）优化行程 → （可选）保存到历史
```

### 7.2 查看历史行程流程

```
首页 → 点击"历史" → 登录检查 → 加载历史列表
→ 点击列表项 → 详情弹窗 → 点击"载入此方案"
→ 数据写入当前行程 → 跳转行程详情页 / 地图页
```

### 7.3 优化已有行程流程

```
行程详情页 → （需有当前行程）→ 进入优化页
→ 输入优化需求 → 点击开始优化
→ Loading → 优化成功 → 自动返回 → 查看新行程
```

## 8. 约束与边界

1. **登录要求**：行程生成、历史记录、个人中心功能必须登录后使用；首页地图无需登录即可查看。
2. **配额限制**：每日 AI 生成次数有限制，超出后需次日重置或通过奖励机制增加。
3. **数据持久化**：行程生成后仅保存在内存（Store）中，必须手动点击"保存"才会写入历史记录。
4. **地图坐标**：所有地图坐标使用 `gcj02` 国测局坐标系，与微信小程序 `<map>` 组件兼容。
5. **网络降级**：历史记录保存失败时自动降级到本地缓存；历史列表加载失败时也尝试读取本地缓存。
